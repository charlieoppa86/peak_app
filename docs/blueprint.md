# Peak — 프로덕트 블루프린트

> 앱 이름: **Peak** · 작성일: 2026-06-07 · 비개발자 솔로 빌드 · Flutter MVP 6~8주 타겟

---

## 1. 서비스 한 줄 정의

날씨가 바뀌면 라이딩 약속도 같이 바뀌는, 로드바이커를 위한 소셜 일정 앱

> 2주 날씨 미리보기 + 최적 시간대 자동 추천 + 문자 기반 바이럴 초대

---

## 2. 문제 정의

| 문제 | 페인 강도 | 발생 빈도 | 근거 |
|---|---|---|---|
| P1. 날씨 앱과 캘린더 앱을 번갈아 보며 최적 라이딩 날짜를 수동으로 판단해야 함 | 상 | 상 | 주 1~2회 일정 수립 시 기상청·애플날씨·구글캘린더 3개 앱 전환 발생; 날씨 변동 시 재판단 필요 |
| P2. 같이 달릴 친구에게 일정 공유가 카카오톡 텍스트 전달로 끝나 참석 여부 추적 불가 | 중 | 상 | 그룹 라이딩 조율 시 단톡방에서 "나 가능" 답장을 수동 카운트; 노쇼율 높음 |
| P3. 날씨 급변(비·강풍) 시 일정 변경 의사결정이 느리고 멤버 공지가 누락됨 | 상 | 중 | 기상 예보 변동 확인 → 단톡 공지 → 재확인까지 리드타임 30분~수 시간 |

## 4. 핵심 가치 제안 (UVP)

> **"날씨 보고 라이딩 잡는 앱, 초대는 문자 한 통"**

경쟁사 대비 차별점:
1. 날씨 점수화 + 캘린더 통합
2. 비개발자도 쓸 수 있는 소셜 초대 UX
3. 초대 → 앱 설치 바이럴 루프

## 5. 비즈니스 모델

### 수익 모델 로드맵

| Phase | 시점 | 전략 |
|---|---|---|
| Phase 1 | 0~6개월 | 무료, 사용자 확보 우선 |
| Phase 2 | 6개월~ | 프리미엄 구독 — 고급 날씨 지표, 무제한 그룹, 루트 저장 |
| Phase 3 | 12개월~ | B2B 동호회 플랜 (관리자 대시보드) |

### 가격 정책

| 플랜 | 가격 | 포함 기능 |
|---|---|---|
| 무료 | 0원 | 개인 일정 + 그룹 1개 + 7일 날씨 |
| 프로 | 월 3,900원 | 고급 날씨 지표, 무제한 그룹, 14일 날씨 |
| 클럽 | 월 9,900원 | 20명 이하 동호회, 관리자 기능 |

### 단위 경제 가설

| 지표 | 목표 |
|---|---|
| CAC | < 2,000원/유저 (바이럴 초대 중심) |
| 무료→유료 전환율 | 5% (월 1회 이상 라이딩 유저 기준) |

## 6. MVP 가설

> **가설:** "날씨 기반 추천 날짜에 라이딩 일정을 잡으면, 그룹 초대 전환율이 단톡방 공유 대비 40% 이상 높다"

### MVP 포함 기능 (4개)

1. **2주 날씨 캘린더 뷰** — 날짜별 라이딩 점수 (0~100점) 표시
   - Open-Meteo 무료 API · 점수 알고리즘 (기온·풍속·강수확률 가중치) · 스크롤 캘린더 위젯
2. **개인 일정 등록** — 날짜·시간·코스명 입력 (3필드 이하)
   - Firestore 저장 · flutter_local_notifications
3. **그룹 초대** — 이름/닉네임 입력 후 참석 처리 · 참석자 실시간 동기화
   - Dynamic Links · Firestore 실시간 반영 · 참석 카운트
4. **날씨 변동 알림** — 강수확률 50% 초과 시 푸시 + 대안 날짜 1개 제안
   - FCM 푸시 · Cloud Functions 스케줄러 (하루 1회 체크)

### MVP 제외 항목

- 운동 기록 (Strava에 위임)
- 루트 지도 / GPX 시각화
- 소셜 피드
- Apple Watch 연동
- Strava 코스 자동 불러오기 (Phase 2)

## 7. 성공 지표

### North Star Metric

**월간 그룹 라이딩 완료 건수**
- 완료 기준: 일정 생성 후 2인 이상 참석 확인
- 날씨 추천 정확도 × 초대 UX × 앱 재방문 세 가지를 동시에 반영
- **6개월 내 목표: 월 500건**

### 보조 지표

| 지표 | 목표 | 의미 |
|---|---|---|
| 바이럴 계수 (K-factor) | ≥ 0.5 | 초대 발송 대비 신규 설치 비율. 앱 성장 자립 여부 판단 |
| 날씨 추천 채택률 | ≥ 60% | 추천 날짜에 실제 일정 등록한 비율. 핵심 기능 유효성 검증 |
| D30 리텐션 | ≥ 30% | 30일 후 재방문율. 캘린더 앱 특성상 주기성 확인 필수 |

## 8. 가장 위험한 가정 (Riskiest Assumptions)

| # | 가정 | 위험 내용 | 검증 방법 |
|---|---|---|---|
| R1 | 날씨 점수를 신뢰해 일정을 바꾼다 | 카카오/기상청 앱에 익숙한 유저가 "또 다른 날씨 앱"으로 인식, Peak 점수를 무시할 가능성 | 랜딩페이지 A/B — "날씨 점수 캘린더" vs "그냥 캘린더" 클릭율 비교 (코딩 전 2주) |
| R2 | SMS 초대 링크가 앱 설치로 전환된다 | 이름/닉네임 입력만으로 참석 처리해 마찰 최소화했지만, 앱 설치까지 이어질 동기가 충분한지 불확실 | 수동 초대 10건 테스트 — 지인에게 SMS 링크 발송 후 설치 완료율 측정 (MVP 빌드 전) |
| R3 | 혼자 타는 유저도 앱을 지속 사용한다 | 솔로 라이더는 날씨 체크 외 재방문 이유가 약함. 솔로 DAU 60% 이상이면 D30 30% 달성 어려움 | 온보딩 설문 — "주로 혼자 vs 그룹" 비율 파악 + 첫 2주 솔로 유저 D7 리텐션 집중 모니터링 |
